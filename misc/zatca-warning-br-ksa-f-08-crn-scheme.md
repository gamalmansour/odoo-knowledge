# ZATCA Warning [BR-KSA-F-08]: Incorrect Value for Scheme ID 'CRN'

| Field         | Value                                      |
|---------------|--------------------------------------------|
| Category      | misc                                       |
| Odoo Versions | 16, 17, 18, 19                             |
| Severity      | 🟡 Medium                                  |
| Last Verified | 2026-09-30                                 |
| Author        | ENG/Gamal Mansour                          |

**Tags:** `zatca`, `l10n_sa_edi`, `e-invoicing`, `saudi-arabia`, `br-ksa-f-08`, `crn`, `vat`, `warning`, `bt-29`, `bt-46`

---

## Problem

When submitting invoices to ZATCA (Fatoora Phase 2 — Clearance or Reporting), the invoice is accepted by ZATCA but returns with a warning in the chatter:

```
[202] BR-KSA-F-08 : [BR-KSA-F-08] - The value provided in Other Seller ID (BT-29) or Other Buyer ID (BT-46) for the scheme ID 'CRN' appears to be incorrect. Please recheck the value to avoid non-compliance.
```

## Root Cause

In the UBL 2.1 XML generated by `l10n_sa_edi`, the Seller (BT-29) or Buyer (BT-46) identification is output under `<cac:PartyIdentification>`:

```xml
<cac:PartyIdentification>
    <cbc:ID schemeID="CRN">310480315700003</cbc:ID>
</cac:PartyIdentification>
```

When `schemeID` is `CRN` (Commercial Registration Number / السجل التجاري), ZATCA's validation rule **BR-KSA-F-08** strictly requires a **10-digit** Saudi Commercial Registration number (e.g. `1010494168` or `700xxxxxxx`).

If a 15-digit Tax Identification Number (VAT / الرقم الضريبي, e.g. `310480315700003`) was erroneously entered into the **Identification Number (SA)** field (`l10n_sa_additional_identification_number`) while the scheme is selected as **CRN**, Odoo outputs the 15-digit VAT number inside `schemeID="CRN"`, triggering the warning from ZATCA.

## Solution ✅

### In the Odoo UI:
1. Navigate to **Settings → Companies → Companies** (or open the company's contact card in **Contacts**).
2. Select the affected company (e.g., *شركة اللمسة الخشبية للتجارة ( الرياض )*).
3. In the **General Information** tab:
   - Find **Identification Scheme** (`l10n_sa_additional_identification_scheme`).
   - In **Identification Number (SA)** (`l10n_sa_additional_identification_number`):
     - Replace the 15-digit VAT number with the company's real **10-digit Commercial Registration number** (e.g. `1010494168`).
     - Alternatively, if using the 700 Unified Number, ensure it is 10 digits (e.g. `700xxxxxxx`).
4. Save the company.

### In PostgreSQL (Direct Fix):
```sql
UPDATE res_partner 
   SET l10n_sa_additional_identification_number = company_registry 
 WHERE id IN (
     SELECT partner_id FROM res_company WHERE id = <company_id>
 )
 AND company_registry ~ '^[0-9]{10}$';
```

## ⚠️ Pitfalls

- The company form has two separate registry fields in Saudi localization:
  1. `company_registry` (Company Registry / السجل التجاري).
  2. `l10n_sa_additional_identification_number` (Identification Number (SA) under the Saudi EDI section).
  Users often mistakenly paste the VAT number into `l10n_sa_additional_identification_number` because both fields are near each other on the form.
- ZATCA accepts the invoice with `PASS_WITH_WARNINGS` or `REPORTED_WITH_WARNINGS`, so the invoice is legally valid, but the warning will persist on every single submitted invoice until the company master data is fixed.

## Verification

Inspect the generated UBL XML for a newly posted invoice:
```xml
<cac:AccountingSupplierParty>
    <cac:Party>
        <cac:PartyIdentification>
            <cbc:ID schemeID="CRN">1010494168</cbc:ID>
        </cac:PartyIdentification>
```
The value must be exactly 10 digits. Submitting to ZATCA should now return clean without warning `[BR-KSA-F-08]`.
