# Odoo Sitemap.xml Fails in Google Search Console with 'Sitemap Could Not Be Read' Due to Unencoded Arabic URLs

## Problem

When submitting `sitemap.xml` to Google Search Console (GSC), Google immediately flags the sitemap with a red error:
```
Sitemap could not be read
```
with 0 discovered pages, even though opening `https://domain.com/sitemap.xml` in a web browser renders cleanly.

## Root Cause

1. **RFC 3986 Non-ASCII Violation**: Odoo's native sitemap generator extracts record slugs and names directly into the XML `<loc>` tags (e.g. `/helpdesk/خدمة-العملاء-1` or `/forum/المساعدة-1`). The XML Sitemap standard and Googlebot's XML parser strictly require all `<loc>` URLs to be URI-encoded (percent-encoded, e.g. `%D8%AE%D8%AF%D9%85%D8%A9...`). When Googlebot encounters raw Arabic or Unicode characters in a `<loc>` node, the XML parser fails and rejects the sitemap.
2. **Double Slash Input Trap in GSC**: In Google Search Console URL-prefix properties, the input box already has `https://domain.com/`. Entering `/sitemap.xml` (with a leading slash) causes GSC to request `https://domain.com//sitemap.xml`.

## Solution ✅

1. **Percent-Encode All Sitemap URLs in Attachment**:
   Odoo caches the sitemap as an `ir.attachment` (e.g. `/sitemap-1-xxxx.xml`). Use a script or backend hook to ensure all `<loc>` URLs are percent-encoded:

```python
import urllib.parse
import re
import base64

att = env['ir.attachment'].search([('name', 'ilike', 'sitemap')], limit=1)
if att:
    raw_xml = att.raw.decode('utf-8') if isinstance(att.raw, bytes) else att.raw

    def encode_loc(match):
        full_url = match.group(1)
        parsed = urllib.parse.urlsplit(full_url)
        quoted_path = urllib.parse.quote(parsed.path, safe='/')
        quoted_url = urllib.parse.urlunsplit((parsed.scheme, parsed.netloc, quoted_path, parsed.query, parsed.fragment))
        return f'<loc>{quoted_url}</loc>'

    clean_xml = re.sub(r'<loc>(https?://[^<]+)</loc>', encode_loc, raw_xml)
    b64_data = base64.b64encode(clean_xml.encode('utf-8')).decode('utf-8')
    att.write({'datas': b64_data, 'mimetype': 'application/xml'})
```

2. **Submit in GSC without Leading Slash**:
   In GSC under **Sitemaps**, type strictly: `sitemap.xml` (not `/sitemap.xml`).

## ⚠️ Pitfalls

- If writing to `ir.attachment` via JSON-RPC, `raw` requires binary `bytes`, or use base64 in `datas` to avoid `TypeError: bin_data must be bytes or bytearray`.
- If the sitemap is regenerated by an Odoo cron job, the cached attachment will be recreated with unencoded URLs unless a patch is applied to `_enumerate_pages` or the attachment is maintained with encoded content.
